# v0.2 问题修复记录

> 2026-06-06

---

## 1. 打开 EPUB 无响应

**现象**：点击「打开」选择文件后无反应

**根因**：使用了 `@tauri-apps/plugin-dialog` 但该插件在运行时未正确初始化（dialog:default 权限未生效）

**解决**：回退到 HTML `<input type="file">` + 前端读取 ArrayBuffer → base64 编码 → 传给 Rust `open_book_base64` 命令

**涉及文件**：
- `main.ts`: 用 file input 替代 dialog 插件
- `reader-core.ts`: `openFromBuffer(data: ArrayBuffer)` 方法
- `lib.rs`: `open_book_base64` 命令接受 base64 字符串
- `epub_parser.rs`: `parse_epub_from_bytes()` 从 `&[u8]` 解析

## 2. container.xml 中未找到 rootfile

**现象**：报错 `container.xml 中未找到 rootfile`

**根因**：`quick-xml` 把自闭合标签 `<rootfile .../>` 解析为 `Event::Empty` 而非 `Event::Start`，原代码只处理了 `Start` 事件

**解决**：同时处理 `Event::Start` 和 `Event::Empty` 事件，并添加简单字符串匹配兜底

**涉及文件**：`epub_parser.rs:parse_container()`

---

## 3. OPF 解析到 0 个 spine 条目 / 路径重复拼接

**现象**：`解析到 0 个 spine 条目` 或路径如 `OEBPS/1/OEBPS/Text/000a.htm`

**根因**：
1. OPF 使用了 `<opf:item>` 命名空间前缀，原代码只匹配 `"item"` 不匹配 `"opf:item"`
2. `resolve_path(opf_dir, href)` 重复拼接了目录前缀（manifest href 已相对 OPF 目录）

**解决**：
1. 匹配 `"item" | "opf:item"` 和 `"itemref" | "opf:itemref"`
2. spine href 不做 resolve_path，保持 manifest 原始值；`read_zip_entry` 用文件名（basename）回退匹配

**涉及文件**：`epub_parser.rs:parse_opf()`, `parse_epub_from_archive()`

---

## 4. html_sanitizer 越界 panic

**现象**：`range end index 487 out of range for slice of length 486`

**根因**：`strip_dangerous_styles` 使用字节索引处理字符串，在 `<body>` 提取后边界计算错误

**解决**：重写 `extract_body`，用 `find` 定位 `<body>` 和 `</body>` 的字节偏移，安全切分

**涉及文件**：`html_sanitizer.rs`

## 5. 中文乱码（»¥åï¼å°±æç）

**现象**：所有中文显示为乱码

**根因**：`strip_dangerous_styles` 按**字节**遍历 UTF-8 字符串，每个字节被强转为 `char`，多字节中文字符被撕裂

**解决**：改为按**字符**遍历（`html.chars().collect()`），保留 UTF-8 完整性

**涉及文件**：`html_sanitizer.rs:strip_dangerous_styles()`

## 6. GBK/GB2312 编码的章节中文仍乱码

**现象**：部分 EPUB 的章节 HTML 使用 GBK 编码，解码后仍乱码

**根因**：`decode_text` 仅依赖 BOM 检测，无 BOM 时默认 UTF-8；GBK 编码文件无 BOM，字节被错误解析

**解决**：编码检测链：BOM → XML/HTML 声明中的 encoding → UTF-8 → GBK 回退

```rust
fn decode_text(raw: &[u8]) {
    1. BOM 检测 → 按 BOM 解码
    2. 解析 <?xml encoding="..."?> 或 <meta charset="...">  → 按声明解码
    3. UTF-8 解码（无错误则返回）
    4. GBK 回退解码
}
```

**涉及文件**：`epub_parser.rs:decode_text()`, `detect_encoding_from_content()`

## 7. 页面出现破图小图标

**现象**：文字前后出现类似缺角图片的小图标

**根因**：EPUB 的 `<img>` 标签引用的图片路径无法解析（相对路径脱离 ZIP 上下文），浏览器显示默认破图图标

**解决**：`strip_img_tags()` 剥离所有 `<img>` 标签，替换为 `[图: alt文本]`

**涉及文件**：`html_sanitizer.rs:strip_img_tags()`

---

## 8. CSS Columns 分页重叠 / 翻页按钮失灵

**现象**：翻页时上一页内容残留到下一页；上/下一页按钮点击无效

**根因**：CSS `column-width` + `translateX` 分页方案不精确，`column-gap: 0` 导致列边界模糊，`recountPages()` 依赖 `requestAnimationFrame` 异步计算不准确

**解决**：替换为简单**垂直滚动视图**：
- `.reader-vp` 使用 `overflow-y: auto`
- `nextPage()`/`prevPage()` 用 `scrollTop += clientHeight * 0.9`
- 键盘支持上下箭头翻页

**涉及文件**：`reader-core.ts`

---

## 9. 目录点击无效 / 空 href 死循环

**现象**：点击目录项无反应，且终端出现大量 `get_chapter: href=` 空字符串日志，重复解析 container.xml

**根因**：
1. NCX 目录中存在无 `<content>` 的导航节点（纯分组标题），其 href 为空字符串
2. `get_chapter("")` → 空 href → `parse_single_chapter` 尝试在 spine 中查找空字符串 → 失败 → 前端重试 → 无限循环
3. 翻页使用 `scrollBy({ behavior: 'smooth' })` 在某些 WebView 中不生效

**解决**：
1. `get_chapter` 和 `parse_single_chapter` 入口检查空 href 并直接返回错误
2. 前端 `loadChapter` 跳过空 href
3. 目录渲染对无 href 的节点改用纯文本标题（非链接）
4. `scrollBy` → 直接设置 `scrollTop` 值

**涉及文件**：`lib.rs`, `epub_parser.rs`, `reader-core.ts`, `main.ts`

---

## 关键架构决策

1. **文件传输**：前端 HTML file input → ArrayBuffer → base64 → Rust base64 decode → ZIP 解析（避免 dialog 插件依赖）
2. **大书支持**：初始只加载 100 章到内存缓存，其余按需从 base64 重新解析（单章约 10-50ms）
3. **路径匹配**：spine 使用 manifest 原始 href，查找时精确匹配 + 文件名回退
4. **命名空间**：OPF 同时匹配 `"item"` 和 `"opf:item"`（兼容不同 EPUB 生成器风格）
5. **分页方案**：放弃 CSS Columns 分页，改用垂直滚动 + `scrollTop` 翻页（更稳定）
