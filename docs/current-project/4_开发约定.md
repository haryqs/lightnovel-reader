# 开发约定

## 文件命名

- Rust: `snake_case`（`epub_parser.rs`, `html_sanitizer.rs`）
- TypeScript: `kebab-case`（`reader-core.ts`, `paginator.ts`）
- 文档: 中文，空格分隔

## 代码风格

- TypeScript 不使用分号（与现有 `reader.ts`、`main.ts` 风格一致）
- 缩进：2 空格
- 字符串：单引号（TypeScript），双引号（Rust）
- 注释：中文，仅解释"为什么"，不解释"是什么"

## 架构约束

1. **UI 层不直接碰解析逻辑**：`main.ts` 只调 `reader-core.ts` 的方法，不直接碰 Rust invoke 或 epub 内部结构
2. **Rust 命令返回 JSON**：所有 Tauri command 返回 `Result<T, String>`，前端不做错误恢复，直接显示错误信息
3. **状态管理**：不做全局 store，状态在 `reader-core.ts` 内部管理，UI 通过回调获取更新

## Git 约定

- commit 信息用中文，写清楚做了什么
- 每次开工前 `git pull`，结束后 `git push`
- 不提交 `node_modules/`、`target/`、`dist/`

## AI 协作约定

1. **不要重写已有文件**：优先用 `edit` 工具做精确修改，避免大块替换
2. **不要引入新依赖**：除非在 `当前项目_阅读器/AI协作指南.md` 中明确批准
3. **保留注释**：现有代码中的中文注释保留并模仿其风格
4. **先读再改**：修改任何文件前先 `read` 确认内容

## 前端零基础假设

- UI 逻辑保持直白：DOM query → 事件绑定 → 方法调用
- 不做高阶抽象（decorator、proxy、complex generics）
- CSS 用变量驱动主题，避免动态样式计算
