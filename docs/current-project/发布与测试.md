## 三、打包

```powershell
npm.cmd run check:release-trust    # 必须先通过正式信任材料检查
npm.cmd run release:build          # 门禁通过后出 NSIS 安装器 + MSI（release）
```

`package:beta` 和 `installer:web` 也通过 npm pre-hook 自动执行同一门禁；所有正式分发入口还会执行
`check:license`，确认根目录是未修改的 AGPL-3.0-only 正文，且 npm/Cargo 包元数据一致。信任门要求：

- `REQUIRE_OFFICIAL_PLUGIN_SIGNATURES = true`；
- `src-tauri/src/plugin_trust.rs` 至少有一枚合法、唯一 keyId 的 32 字节 Ed25519 公钥；
- `src-tauri/tauri.conf.json` 的 updater `pubkey` 非空；
- `bundle.createUpdaterArtifacts = true`，确保构建实际生成更新签名产物。

插件仓库签名公钥与 Tauri updater 公钥是不同用途的信任材料，必须分别生成和管理。首批公钥已于 2026-07-25
注入仓库，`check:release-trust` 已转绿；实际 `release:build` 仍必须从仓库外秘密管理注入 updater 私钥路径和密码，
不得把私钥、密码或临时明文写入仓库。

```powershell
powershell -ExecutionPolicy Bypass -File scripts/build-signed-updater.ps1 `
  -PrivateKeyPath "<仓库外 updater 私钥路径>"
```

脚本会用 `Read-Host -AsSecureString` 提示输入密码，临时注入 Tauri 签名环境变量，并在成功或失败后清理环境变量与
非托管密码缓冲；不要把密码写进命令历史、脚本参数或仓库文件。`tauri build` 实际读取
`TAURI_SIGNING_PRIVATE_KEY`（值可为仓库外私钥路径），而独立的 `tauri signer sign` 还支持
`TAURI_SIGNING_PRIVATE_KEY_PATH`；脚本会兼容设置两者，但不会读取或打印私钥内容。它只构建 updater 实际使用的 NSIS，避免可选 MSI
故障阻断更新产物。完整 `release:build` 仍会同时构建 NSIS/MSI；MSI 可先用
`npm.cmd run tauri -- build --bundles msi --no-sign` 单独诊断。构建完成后，从实际 NSIS 安装器与 `.sig` 生成
GitHub Release 静态更新清单：

```powershell
npm.cmd run prepare:updater-release -- `
  --bundle-dir E:\lightnovel-reader-release-staging\v0.7.2-updater-input `
  --out-dir E:\lightnovel-reader-release-staging\v0.7.2-updater `
  --base-url https://github.com/haryqs/lightnovel-reader/releases/download/v0.7.2 `
  --notes "优化应用内更新：版本详情、下载进度、验签安装阶段与失败重试"
```

`latest.json` 的 `platforms.windows-x86_64.signature` 必须是 `.sig` 文件内容，不是文件路径；生成器会同时复制
NSIS 安装器和 `.sig`，已有输出默认拒绝覆盖。版本默认读取 `src-tauri/tauri.conf.json`；显式传
`--version` 时也必须与该配置一致，避免误用 npm 包版本。
`--bundle-dir` 下必须只有 `nsis/<当前版本安装器>` 与对应 `.sig`；长期工作区的 `target` 可能保留多个历史版本，
生成器会按设计拒绝猜测。先把当前两文件复制到独立输入目录，不删除或覆盖历史 bundle。

将 updater 三资产与已签名的 `repository.json` / 插件 zip 放入同一个候选目录后，上传前执行统一验收：

updater 签名文本、插件 SHA-256/大小与 Ed25519 签名。任何旧 tag、篡改包、额外中间文件或密钥文件都会阻断。

## 五、发版边界

- 便携包/Web 安装器不是自动更新器。v0.7.0 是新 updater 密钥下的首个公开版本，且公开二进制尚无应用内
  更新按钮；它包含 updater 后端和权限，可用于底层链路验证，但不能声称用户能从 v0.7.0 界面发起更新。
  v0.7.1 是首个带手动更新入口的公开版本，完整用户界面检查、下载、验签、安装和重启闭环应从 v0.7.1 更新到
  后续版本验证。开发主线已增加应用内版本/发布日期/发布说明详情、下载字节/百分比、验签安装阶段和重复安装
  保护，但当前同版本 Latest 只能验证详情弹窗壳、检查分支与进度默认隐藏；在跨版本实测前不得宣称真实更新
  元数据填充、下载进度、安装或重启已通过。
- 公开草稿前，发布目标提交必须包含 updater 点号资产名修复、AGPL-3.0-only 根许可证与许可证发布门；
  不允许让安装资产与 Release 自动生成的源代码归档指向不同实现状态。
