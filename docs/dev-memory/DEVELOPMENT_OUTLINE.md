> 目标：把后续开发从“想到哪做到哪”整理成可执行路线。本文负责方向和阶段边界；具体任务列表维护在 `NEXT_ACTIONS.md`。

## 当前基线

项目已经从原型阅读器推进到“本地优先轻小说平台”的早期实现阶段。阅读器仍是核心内核，
但产品目标已经扩展为发现、索引、收藏、整理、合法获取入口和多阅读方式的一体化平台。

已具备：

- Tauri v2 桌面壳。
- `reading-core` Rust 核心。
- TypeScript 阅读引擎。
- EPUB 解析与 HTML 清洗。
- 虚拟分页、单页/双页、三主题、字号/版式调节。
- 目录导航。
- 阅读进度持久化。
- 高亮/批注/书签与 Markdown 导出。
- SQLite 本地书库。
- SHA-256 对象仓库去重。
- Calibre 作为导入来源。
- 单本/多本 EPUB 直接导入书库。
- 插件 SDK 契约草案。
- 插件 manifest 宿主侧校验骨架（`reading-core::plugin_manifest`）。
- 桌面 QuickJS 插件运行时与 `search → getBook → getChapter` 完整试跑。
- 项目记忆与开发流程工具。

当前定位修订（2026-06-21）：

- 产品不是“只打开 EPUB 的阅读器”，而是本地优先轻小说平台。
- 内置阅读器、系统浏览器、本机其它阅读器都应成为可选阅读方式。
- 公共版权、开放授权、用户自有资源，以及经 ToS/授权确认可获取的官方免费资源，可以进入站内获取/
  缓存/阅读流程。
- 商业、受保护或未知授权正文只保存元数据与官方入口，不自动抓取、不缓存、不镜像。

当前最重要的事实：**v0.3-v0.6.5 产品闭环和 v1.0 四阶段架构已落地；当前主线是 v0.7 桌面插件来源收口。
QuickJS/host API/完整试跑、正式 `source.*` 来源收藏、开放 EPUB 获取、真实离线 Tauri smoke、每域限速与条款门均已落地；
官方仓库 Ed25519 包验签、正式发布 keyring 与 Gutenberg 公网搜索到获取全链路已通过；
当前剩余收口是公开统一 GitHub Release 并完成旧版本到 v0.3.1 的真实在线更新。**

## 开发原则

1. **本地体验先于在线资源**
   没有稳定阅读、书库、标注，在线资源越多越会放大混乱。

2. **书库模型先简后繁**
   当前 `books` 单表可继续服务 v0.3。`series/work/volume/edition/asset` 的完整模型等真实需求出现后再迁移。

3. **协议自由期要快，但要守纪律**
   v0.5 之前可以改桥接协议；每次改动必须同步 TS、Rust、文档。

4. **功能必须可验证**
   每个阶段都要有明确验收标准。不能靠“看起来实现了”结束。

5. **合规进入能力层**
   在线资源和插件必须有授权状态、风险等级、能力限制，不靠口头声明。

6. **阅读方式显式选择**
   任何远程或本地条目都不应该只有一个“打开”含义。平台应按授权和可用性提供明确选择：
   浏览器打开官方页、用内置阅读器打开、用外部本地阅读器打开。

## v0.3：本地书库闭环

目标：用户可以长期把 EPUB 放进自有书库，而不是只临时打开文件。

### 范围

- 单本/多本 EPUB 导入。
- Calibre 批量导入。
- 去重。
- 书架列表。
- 搜索。
- 最近阅读排序。
- 按书库 id 打开。
- 封面提取。
- series / series_index 元数据。
- 基础错误报告。

### 验收标准

- `npm.cmd run build` 通过。
- `cargo test --workspace` 通过。
- 实机可导入单本 EPUB。
- 实机可导入 Calibre 来源。
- 重复导入不会复制文件。
- 搜索中文标题/作者可命中。
- 从书库打开后，最近阅读时间更新。
- 关闭重开后能恢复阅读位置。

### 推荐实现顺序

1. 补完实机冒烟测试。
2. 提交当前 v0.3 本地书库基线。
3. 根据实机冒烟结果修复封面 URL、文件权限或导入反馈细节。
4. 文档更新与 v0.3 标记。

## v0.5：在线元数据与合法入口

目标：开始把“资源发现”接进来，但只做元数据和合法入口。

### 范围

- 粘贴链接识别。
- 官方页面记录。
- 购买/借阅/免费阅读入口。
- 来源授权状态字段。
- source 表 v1。
- 结构化错误码评估。
- 桥接协议冻结前审计。

### 不做

- 不抓受保护正文。
- 不内置盗版源。
- 不绕过登录/付费/DRM。

### 验收标准

- 每条在线来源都有 `rights_status` / `risk_level`。
- 未确认授权来源只能保存链接与元数据。
- 文档和 UI 都能区分“可下载”“只跳转”“只元数据”。

## v0.6.5：阅读方式选择与合法开放资源获取体验

目标：把平台从“点卡片后自动决定怎么打开”升级为“按授权和可用性给用户明确选择阅读方式”。

### 范围

- 统一条目动作模型：浏览器打开、内置阅读器打开、外部本地阅读器打开、获取/缓存后打开。
- 本地或 cached asset：可用内置阅读器，也可交给系统默认应用/外部阅读器。
- 远程 metadata-only 条目：默认浏览器打开官方入口。
- 公共版权或开放授权条目：可选择获取正文/EPUB，缓存为本地 asset 后用内置阅读器打开。
- 未来外部阅读器设置：记录用户偏好的外部阅读器路径或系统默认打开方式。
- UI 文案必须清楚显示“站内读 / 浏览器 / 外部阅读器 / 仅外链”的区别。

### 不做

- 不抓商业站正文。
- 不把 `official_free` 直接等同于可缓存正文；仍需来源 ToS/授权确认。
- 不在没有用户选择的情况下后台批量下载远程正文。

### 验收标准

- 远程卡片不再只有模糊的“打开”，而是能按 `availability`、`rightsStatus`、`remoteUrl` 推导可用动作。
- 公共版权/开放授权条目可通过显式选择进入 acquire，然后用内置阅读器打开。
- 本地/cached 条目可用内置阅读器打开；外部阅读器能力若未实现，UI/文档明确列为待办，不伪装完成。
- 非授权条目只提供浏览器/官方入口，不出现“获取正文”入口。

## v0.7：插件运行时

目标：实现用户可扩展的 source adapter，但保持安全边界。

### 范围

- QuickJS 桌面运行时。
- `plugin-sdk` manifest 校验。
  - 已完成：`reading-core::plugin_manifest` 解析/校验 manifest、权限/能力去重、精确域名白名单与合规提示。
  - 已完成：`reading-core::plugin_package` / `plugin_store` 支持 zip 安装包预览、本地写入、启停/卸载与已安装列表。
- SDK `export default` / Promise / DTO 运行时校验。
- `host.http` 域名白名单。
- `host.html` 解析能力。
- `host.kv` 私有存储。
- 官方白名单示例源。
- 插件面板完整流程试跑。
- 正式来源列表、分页搜索、书籍/章节读取与纯文本章节预览。
- 用户显式收藏插件书籍为远程 `source_record`；搜索不自动落库，不自动获取正文。
- 可选 `acquire` 只为 `public-domain/open-license` 返回 EPUB 提案；宿主复核后写入 `cached` asset 并可直接阅读。
- 官方仓库包在 SHA-256 后对 zip 原始字节做 Ed25519 验签；预览/安装分别复验，私钥永不进入客户端仓库。

### 验收标准

- 插件不能访问文件系统。
- 插件不能访问未声明域名。
- 插件安装时显示权限与合规信息。
- 官方示例源可搜索、取书目、取章节。
- 已启用插件可出现在在线来源选择器；停用后立即退出正式来源列表。
- 收藏同一插件书籍保持幂等，书架来源面板可看到 `sourceKind=plugin` 记录。
- 声明 `acquire` 的公共版权/开放授权示例可“获取并阅读”；official-free/user-declared 不能自动缓存正文。
- 对外启用官方仓库前，正式发布公钥进入编译内 keyring，索引全部签署并开启强制签名模式。
