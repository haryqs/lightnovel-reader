## 一、代码与命名约定

- 文件名：Rust `snake_case`（`epub_parser.rs`）；TypeScript `kebab-case`（`reader-core.ts`）；文档中文。
- TS 代码：**不写分号**、2 空格缩进、字符串用单引号；Rust 字符串用双引号。
- 注释用中文，只解释“为什么”，不解释“是什么”；改代码时保留并模仿既有注释风格。
- Tauri command 一律返回 `Result<T, String>`；前端不做错误恢复，直接展示。
- UI 层（`main.ts`）只调 `reader-core.ts`，不直接碰 Rust invoke 或 EPUB 内部结构。

## 二、AI 协作约定

- **先读再改**：改任何文件前先 Read 确认内容，不凭记忆改。
- 优先用精确 Edit，不整文件重写。
- 不引入新依赖，除非收益明确且写入 `DECISIONS.md`。
- commit 信息用中文，写清楚做了什么。

## 三、工程陷阱（都踩过一次，别再踩）

1. **`reader-img` 协议在 Windows 的形态**：WebView2 下正文图片必须是
   `http://reader-img.localhost/<path>`，不是 `reader-img://localhost/...`（后者不解析→破图）。
   已在 `html_sanitizer.rs::img_html` 用 `#[cfg(windows)]` 处理；新壳实现该 scheme 时注意。
2. **FTS5 trigram 最少 3 字**：`library::search_books` 对 <3 字查询走 LIKE 兜底，是设计而非疏漏。
   默认 `unicode61` tokenizer 对 CJK 不可用（连续汉字并成一个 token），不要换回。
3. **serde 禁止单字段 rename**：标注 `kind` 曾被 Rust 重命名为 `type`，导致前端发 `kind` →
   反序列化必败 → 高亮静默存不进库。wire 字段一律 camelCase；数据库列名与 wire 名解耦时，
   在 SQL 层映射（如标注表列名是 `type`，DTO/wire 是 `kind`），不要用 serde rename。
4. **bookId 双端同源**：前端 `computeBookId`（annotations.ts）与 core `compute_book_id`（lib.rs）
   都是 SHA-256 前 32 hex，改任一边必须同步。`books.id` / `asset.id` 也是同一哈希 →
   进度/标注自动跟书走、文件改名移动不丢。
5. **EPUB 编码检测链**：BOM → XML/HTML 声明的 encoding → UTF-8 → GBK 兜底。无 BOM 的 GBK 文件
   只靠 BOM 检测会乱码。处理字符串按**字符**遍历，不按字节（多字节 CJK 会被字节强转撕裂）。
6. **NCX 自闭合 `<content src/>`**：quick-xml 把自闭合标签解析为 `Event::Empty` 而非 `Event::Start`；
   需 `expand_empty_elements=true` 或同时处理两种事件，否则目录 href 全空、点不动。
7. **Gutenberg 式 EPUB 单章 6 万 px**：整本塞进一个巨章。虚拟页分页就是为它做的；改分页逻辑前
   先用大单章书回归。

## 四、安全清洗（不可信 EPUB → 主文档 innerHTML）

正文经 `content.innerHTML` 注入主文档（持有 `window.__TAURI__`、CSP=null）。`html_sanitizer::sanitize_security`
必须先剥脚本/事件处理属性/`javascript:` URL（含 HTML 实体编码绕过）。改清洗输出逻辑时，记得把
`parse_cache.rs` 的 `CACHE_VERSION` +1，否则旧缓存会喂出过期 HTML。详见 `DECISIONS.md` 2026-06-13。

## 五、远期点子（非当前任务，记着别忘）

- **扫描版 PDF 的 OCR**：用户核心书有扫描版 PDF（无文字层）。v2 PDF 阶段，Rust 端 OCR 让扫描经典
  可搜索/可标注，是真差异化方向。PDF 渲染选型：`mupdf` crate（AGPL 对口），实测打开 70MB 扫描件
  5–30ms、翻页 13ms，远胜 PDF.js。
- **标注锚模型**：正文是清洗后的 HTML，CFI 会脆。主锚用"字符位置 + 文本引用兜底（TextQuote）"
  更稳，且能跨 TXT/PDF 统一。
