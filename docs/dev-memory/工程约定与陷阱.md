# 工程约定与陷阱

> 合并自原 `current-project/4_开发约定`、`6_v0.2问题修复记录`、`7/8_交接` 的持久部分。
> 一次性、点对点的状态/交接已删除；这里只留"以后还会再踩"的约定与陷阱。

## 一、代码与命名约定

- 文件名：Rust `snake_case`（`epub_parser.rs`）；TypeScript `kebab-case`（`reader-core.ts`）；文档中文。
- TS 代码：**不写分号**、2 空格缩进、字符串用单引号；Rust 字符串用双引号。
- 注释用中文，只解释“为什么”，不解释“是什么”；改代码时保留并模仿既有注释风格。
- Tauri command 一律返回 `Result<T, String>`；前端不做错误恢复，直接展示。
- UI 层（`main.ts`）只调 `reader-core.ts`，不直接碰 Rust invoke 或 EPUB 内部结构。

## 二、AI 协作约定

- **先读再改**：改任何文件前先 Read 确认内容，不凭记忆改。
- 优先用精确 Edit，不整文件重写。
- 不引入新依赖，除非收益明确且写入 `DECISIONS.md`。
- commit 信息用中文，写清楚做了什么。

## 三、工程陷阱（都踩过一次，别再踩）

1. **`reader-img` 协议在 Windows 的形态**：WebView2 下正文图片必须是
   `http://reader-img.localhost/<path>`，不是 `reader-img://localhost/...`（后者不解析→破图）。
   已在 `html_sanitizer.rs::img_html` 用 `#[cfg(windows)]` 处理；新壳实现该 scheme 时注意。
2. **FTS5 trigram 最少 3 字**：`library::search_books` 对 <3 字查询走 LIKE 兜底，是设计而非疏漏。
   默认 `unicode61` tokenizer 对 CJK 不可用（连续汉字并成一个 token），不要换回。
3. **serde 禁止单字段 rename**：标注 `kind` 曾被 Rust 重命名为 `type`，导致前端发 `kind` →
   反序列化必败 → 高亮静默存不进库。wire 字段一律 camelCase；数据库列名与 wire 名解耦时，
   在 SQL 层映射（如标注表列名是 `type`，DTO/wire 是 `kind`），不要用 serde rename。
4. **bookId 双端同源**：前端 `computeBookId`（annotations.ts）与 core `compute_book_id`（lib.rs）
   都是 SHA-256 前 32 hex，改任一边必须同步。`books.id` / `asset.id` 也是同一哈希 →
   进度/标注自动跟书走、文件改名移动不丢。
5. **EPUB 编码检测链**：BOM → XML/HTML 声明的 encoding → UTF-8 → GBK 兜底。无 BOM 的 GBK 文件
   只靠 BOM 检测会乱码。处理字符串按**字符**遍历，不按字节（多字节 CJK 会被字节强转撕裂）。
6. **NCX 自闭合 `<content src/>`**：quick-xml 把自闭合标签解析为 `Event::Empty` 而非 `Event::Start`；
   需 `expand_empty_elements=true` 或同时处理两种事件，否则目录 href 全空、点不动。
7. **Gutenberg 式 EPUB 单章 6 万 px**：整本塞进一个巨章。虚拟页分页就是为它做的；改分页逻辑前
   先用大单章书回归。
8. **Cargo 可选 feature 会藏住死代码**：`plugin_runtime` 曾在 `cargo test --workspace` 下只编译到
   `#[cfg(not(feature = "quickjs"))]` 空壳，Tauri 也没有开启 feature，因此看似“已集成”但真实代码不能编译。
   改运行时后至少跑 `cargo test -p reading-core --features quickjs` 和 `cargo check -p reader`。
9. **fake-IP DNS 与插件内网防护冲突**：当前 Codex 环境会把公网域名解析到 `198.18.0.0/15`，
   而插件 HTTP 沙箱会按安全设计拒绝该保留网段。真实插件联网 E2E 应换到正常公网 DNS 环境；
   不要为了让测试通过而在生产运行时隐式放行保留网段。
10. **浏览器 WASM 不是 TypeScript 编译产物**：`src/web/reading-core-wasm.ts` 和分页 Worker 静态引用
    `src/worker/reading-core-wasm/reading_core.js`；只改 Rust 源码不会自动刷新这组绑定。相关 core 代码或导出变化后，
    必须运行 `npm.cmd run build:wasm` 并提交四个生成文件；`check:wasm` 只检查产物存在、WASM 文件头和必要导出，
    不能判断二进制是否与 Rust 源码完全同步。
11. **插件返回值仍是不可信输入**：通过 serde DTO 不代表 URL 可安全打开或内容适合直接进 DOM。
    正式 `source.*` 必须继续校验返回 URL 属于 manifest 精确域名、限制结果/章节/文本尺寸，并由 core 清洗章节 HTML。
    插件来源面板的章节预览当前只提取纯文本；不要把插件返回的 HTML 直接 `innerHTML` 到持有 Tauri 能力的主文档。
12. **AcquireProposal 不是下载授权**：`source.acquire` 必须由 core 再按 manifest legal kind、提案 rights status、
    capability 和精确域名裁决；当前只接收 `public-domain/open-license + application/epub+zip`。EPUB 字节由壳侧下载后
    直接交给对象仓库，不能塞进前端 bridge，也不能让 `source.collect` 顺便下载。
13. **签名必须覆盖实际下载字节并在安装时重验**：官方仓库 `signature.value` 是 zip 原始字节的 Ed25519 签名，
    不是 `packageSha256` 字符串或索引 JSON 的签名。预览验签结果不可缓存给安装；安装必须重新下载、核对哈希并验签。
    私钥只允许位于仓库外的秘密存储，代码库和测试夹具只能保留公钥。
14. **GitHub Release 会把资产名中的空格改为点号**：Tauri NSIS 默认生成的安装器名包含空格，
    直接上传后 GitHub 资产会变成 `LightNovel.Reader_...exe`。`latest.json` 若仍指向带空格名将 404。
    `prepare:updater-release` 会在输出和 URL 中预先将空格改为点号；发布前必须再以 GitHub 返回的资产名和摘要复核。
    该工具还要求输入 `nsis` 目录只有一个安装器；`target` 留有多版本时应复制当前 exe/`.sig` 到隔离输入目录，
    不要删除历史产物或用 `--force` 让工具猜测。
15. **密钥备份不能只检查复制和哈希，还要验证当前账户实际可读**：收紧 NTFS ACL 时曾把文件级 DACL 留空，
    导致文件虽存在且所有者正确，当前账户仍无法读取。备份后应从每个副本实际打开公钥并只读检查私钥文件；
    恢复时只对所需的精确文件授予当前账户权限，不递归放宽整个秘密目录，并保留另一份封存副本。
16. **WebDriver 固定端口可能与代理软件冲突**：本机 FlClashCore 曾占用 EdgeDriver 默认端口 9515，使 smoke
    在应用启动前报 `bind 0x271D`。先用 `Get-NetTCPConnection` 查 4444/9515；不要关闭代理或误判应用崩溃，
    改用 `--driver-port <空闲端口> --native-port <空闲端口>` 运行同一测试即可。
17. **PWA Service Worker 不能无条件注入桌面壳**：Tauri WebView2 与浏览器共用 Web 平台 API，旧注册和 HTTP
    缓存可能让新版 `reader.exe` 显示旧前端。Service Worker 只在 Web/PWA 手动注册；Windows 必须在 Builder
    创建 WebView2 前一次性删除 Cache/Code Cache/Service Worker，前端再注销残留注册。生产构建后必须用
    `check:pwa-boundary --dist` 阻止 `registerSW.js` 被再次注入。
18. **多语言 NSIS 的 `passive` 仍可能交互**：Tauri updater 的 passive 参数不能绕过 NSIS 的 Installer Language
    对话框，安装器会在应用退出后静默等待。Windows updater 固定 `installMode = "quiet"`；发布门必须检查它。
    WebDriver 的进程树清理会干扰 updater 子进程，真实安装只能由专用直接启动/CDP smoke 执行。

## 四、安全清洗（不可信 EPUB → 主文档 innerHTML）

正文经 `content.innerHTML` 注入主文档（持有 `window.__TAURI__`、CSP=null）。`html_sanitizer::sanitize_security`
必须先剥脚本/事件处理属性/`javascript:` URL（含 HTML 实体编码绕过）。改清洗输出逻辑时，记得把
`parse_cache.rs` 的 `CACHE_VERSION` +1，否则旧缓存会喂出过期 HTML。详见 `DECISIONS.md` 2026-06-13。

## 五、远期点子（非当前任务，记着别忘）

- **扫描版 PDF 的 OCR**：用户核心书有扫描版 PDF（无文字层）。v2 PDF 阶段，Rust 端 OCR 让扫描经典
  可搜索/可标注，是真差异化方向。PDF 渲染选型：`mupdf` crate（AGPL 对口），实测打开 70MB 扫描件
  5–30ms、翻页 13ms，远胜 PDF.js。
- **标注锚模型**：正文是清洗后的 HTML，CFI 会脆。主锚用"字符位置 + 文本引用兜底（TextQuote）"
  更稳，且能跨 TXT/PDF 统一。
