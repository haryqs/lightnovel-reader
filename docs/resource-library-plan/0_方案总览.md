# 轻小说平台资源书库方案总览

> 目的：把“开源、免费、本地优先、合法边界清晰的轻小说平台”构想整理成可评审方案，
> 供后续 AI 或人类开发者继续批判、补充、落地。阅读器是平台核心模块，但不是完整边界。

## 一句话结论

不要把产品做成“内置全网轻小说资源的 App”，而应做成：

**本地优先的开源轻小说平台 + 内置阅读器 + 全球轻小说书目图谱 + 合法资源入口 + 用户自有书库 + 多阅读方式。**

这样既能追求最大资源覆盖，又尽量避开版权、反爬、维护和平台政策风险。

平台不把“正文聚合”作为资源丰富度来源；平台通过作品索引、版本关系、来源记录、官方入口、
公共版权/开放授权获取、用户自有文件和插件能力来获得长期价值。

## 核心判断

1. **Calibre 不适合作为底层书库**
   - Calibre 的目录结构和数据模型偏“个人电子书管理”，对轻小说的系列、卷、版本、译本、Web 版、文库版、跨语种关系表达不足。
   - 本项目应自建书库模型，但可以保留 Calibre 导入能力。

2. **在线能力应该做，但不能变成盗版聚合**
   - 可以接入 OPDS、官方目录、开放授权资源、公共版权资源、书店/图书馆/官网入口。
   - 不应内置侵权资源站规则，不应绕过付费、登录、DRM 或平台访问限制。

3. **开源免费不自动免除版权责任**
   - 代码开源免费，只说明软件授权方式。
   - 如果软件复制、缓存、分发受版权保护的小说正文，仍可能侵犯复制权、发行权或信息网络传播相关权利。

4. **资源最大化的正确方向是“索引化”**
   - 尽量聚合书目、元数据、版本关系、语种关系、官方链接、合法获取入口。
   - 正文内容只来自用户本地文件、公共版权、开放授权或明确许可来源。

5. **阅读方式需要成为平台能力**
   - 同一条目可能适合浏览器打开、内置阅读器打开或外部本地阅读器打开。
   - UI 不应把所有条目都压成一个“打开”按钮，而应按授权状态和资产状态给出可解释选项。
   - 合法开放资源可以获取并缓存；商业/未知授权资源只跳官方入口。

## 方案分层

```text
┌────────────────────────────────────────────┐
│ 应用层：阅读、搜索、书架、进度、标注、导出   │
├────────────────────────────────────────────┤
│ 书库层：SQLite 元数据 + 内容哈希对象仓库     │
├────────────────────────────────────────────┤
│ 资源层：OPDS / 官方链接 / 开放源 / 用户源    │
├────────────────────────────────────────────┤
│ 合规层：授权状态、风险标记、能力限制         │
└────────────────────────────────────────────┘
```

## 与当前阅读器项目的关系

当前仓库中的阅读器项目已经收敛为：

- Tauri v2
- Rust 解析 EPUB
- 纯 TypeScript + Vite 前端
- 离线优先
- AGPL v3
- 不做 SaaS / 订阅制

本方案不推翻这些约束，而是讨论未来“轻小说资源书库层”如何设计。
