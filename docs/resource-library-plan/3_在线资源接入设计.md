# 在线资源接入设计

## 总原则

在线能力可以做，但应该是“连接器”，不是“资源站”。

目标：

- 帮用户发现书。
- 帮用户识别版本。
- 帮用户找到合法获取入口。
- 帮用户把已有文件和全局书目关联起来。
- 帮用户在合法前提下选择阅读方式：浏览器、内置阅读器、外部本地阅读器。

非目标：

- 分发盗版正文。
- 内置盗版源。
- 批量抓取商业站正文。
- 绕过平台访问限制。
- 把“官方免费可读”自动解释为“允许第三方客户端下载、缓存和站内呈现”。

## 在线与离线统一模型

一本书可以有以下状态：

```text
remote_only     只知道在线记录，还没有本地文件
metadata_only   只有书目信息
external_link   只能跳转外部页面
cached          已缓存开放授权或公共版权内容
local_file      已导入本地文件
missing         记录存在，但文件丢失
blocked         明确高风险或侵权来源
```

UI 不应把在线书和本地书分裂成两个世界，而应显示同一部作品下的不同来源与状态。

UI 也不应把所有状态压成一个“打开”。推荐按状态展示动作：

```text
open_in_browser       跳官方页面/购买页/官方阅读页
open_in_builtin       用内置阅读器打开本地或 cached asset
open_in_external      用系统默认应用或用户指定阅读器打开本地/cached asset
acquire_then_builtin  明确授权资源先获取/缓存，再用内置阅读器打开
```

> 落地说明（2026-06-13）：上述状态混合了「资产状态」与「来源授权」两个维度，
> v0.5 schema 实体化时拆为两个正交字段：`asset.availability`
> （local / remote / missing / cached）×
> `source_record.rights_status`（下方授权状态九值）。
> `metadata_only` / `external_link` 是「无 asset、只有 source_record」的自然结果，
> 不设专门状态。`blocked` 是来源属性，挂在 source / source_record 上。

## 推荐优先接入方式

### 1. OPDS

OPDS 是电子出版物目录协议，适合做合法目录订阅、馆藏目录和开放电子书目录。

建议优先支持：

- OPDS 1.x：兼容现有生态。
- OPDS 2.0：JSON 模型更适合现代客户端。

能力：

```text
浏览目录
搜索书目
读取元数据
发现下载/获取链接
识别授权状态
```

### 2. 官方链接识别器

用户粘贴 URL 后，程序尝试识别：

```text
出版社页面
作者官网
官方连载页
电子书商店页
图书馆借阅页
公共版权目录页
开放授权项目页
```

识别后只做合规能力：

- 抽取书名、作者、卷数、封面、简介等元数据。
- 保存官方链接。
- 标记购买、借阅、免费阅读或未知状态。
- 不默认抓取正文。

### 3. 元数据源

可接入只提供书目信息的源，例如：

- ISBN 数据源
- 出版社目录
- 开放书目数据库
- 社区维护的轻小说元数据包

这些源不提供正文，但对资源发现非常有价值。

### 4. 用户私有源

允许高级用户添加本地或私有来源，例如：

- 本地文件夹
- 自建 OPDS
- 自己的网盘同步目录
- 私人 Git 仓库中的开放授权文本

原则：

- 默认只在本机使用。
- 不上传到官方市场。
- 不作为官方推荐源。

## Source Adapter 接口

> 2026-06-13：本接口与文档 9 插件契约统一为「必选 + 可选 capability」分层，
> 以文档 9 第五节为准——必选 `search / getBook / getChapter`，
> 可选 `browse / resolveUrl / fetchMetadata / acquire`（manifest 声明）。
> 本节的 `fetch_catalog` 即 `browse`。

建议每个来源适配器只暴露有限能力：

```text
search(query)
resolve_url(url)
fetch_metadata(remote_id)
fetch_catalog(path)
acquire(remote_id, mode)
```

其中 `acquire()` 必须返回授权状态和获取方式：

```text
open_download
official_reading_page
purchase_page
lending_page
user_import_required
metadata_only
unsupported_due_to_rights
unknown
```

`mode` 不应只是“下载”。它应表达用户选择的阅读意图，例如：

```text
builtin_reader
external_reader
browser
cache_only
```

其中 `builtin_reader` / `external_reader` 只有在来源允许获取正文或已有本地/cached asset 时才可执行。

## 授权状态

每条来源记录都应标记：

```text
public_domain        公共版权
open_license         开放授权
official_free        官方免费阅读
official_purchase    官方购买入口
official_lending     官方/图书馆借阅入口
user_owned           用户自有文件
metadata_only        只提供书目信息
unknown              未确认授权
blocked              明确侵权或高风险
```

## 能力限制矩阵

| 授权状态 | 显示元数据 | 跳转外链 | 下载 | 缓存正文 | 本地阅读 |
|---|---:|---:|---:|---:|---:|
| public_domain | 是 | 是 | 是 | 是 | 是 |
| open_license | 是 | 是 | 是 | 是 | 是 |
| official_free | 是 | 是 | 视许可 | 视许可 | 视许可 |
| official_purchase | 是 | 是 | 否 | 否 | 用户导入后可以 |
| official_lending | 是 | 是 | 视平台许可 | 视平台许可 | 视平台许可 |
| user_owned | 是 | 可选 | 是 | 是 | 是 |
| metadata_only | 是 | 是 | 否 | 否 | 否 |
| unknown | 是 | 是 | 否 | 否 | 否 |
| blocked | 否 | 否 | 否 | 否 | 否 |

> 本矩阵是合规模型的核心执行点，必须在 reading-core（Rust 宿主侧）强制实现，
> 不信任适配器/插件自报的授权状态决定放行。（2026-06-13）

补充（2026-06-21）：`official_free` 只表示官方提供免费阅读入口，不自动表示允许第三方客户端抓取、
缓存或重新呈现正文。只有当来源 ToS、API 或许可证明确允许时，才可从“浏览器打开”升级为
`acquire_then_builtin` / `open_in_external`。

## 插件市场边界

可以做插件，但官方插件市场必须审核：

- 插件是否绕过登录、付费、DRM。
- 插件是否批量抓取受保护正文。
- 插件是否伪装请求规避平台限制。
- 插件是否声明授权状态。

官方插件市场应只接受低风险来源。

社区可以自行分发插件，但主项目不应背书。
