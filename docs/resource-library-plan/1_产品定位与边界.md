# 产品定位与边界

## 产品愿景

做一款开源、免费、无广告、本地优先、跨平台、体验极佳的轻小说平台。

它不是“阅读器再加几个按钮”，而是围绕轻小说作品、来源、资产和阅读方式组织的个人平台。
内置阅读器是最重要的核心模块，但平台还应负责发现、索引、收藏、整理、合法获取入口和外部阅读方式。

它应当解决中文轻小说阅读生态中的几个问题：

- 阅读器广告多、臃肿、体验差。
- 资源分散，官方、书店、翻译、公共资源站、用户本地文件割裂。
- 很多应用把“资源聚合”建立在侵权正文分发上，长期不可持续。
- 用户自己的书库、进度、标注、笔记难以迁移。

## 产品不应该是什么

不应做成：

- 盗版轻小说聚合 App
- 带广告的资源站客户端
- 需要账号和服务器才能工作的 SaaS
- 依赖单一资源站生存的壳应用
- 为绕过版权、付费、登录、DRM 而设计的工具

## 产品应该是什么

应该做成：

```text
阅读器本体：本地优先、极快、干净、可长期维护
书库系统：表达系列、卷、版本、语种、来源、文件、标注
在线连接：发现合法来源、聚合元数据、跳转官方入口
阅读方式：浏览器 / 内置阅读器 / 外部本地阅读器由用户选择
用户主权：用户掌握自己的文件、进度、标注和导出数据
```

## 核心边界

### 可以做

- 本地 EPUB / TXT / HTML / PDF 导入。
- 用户自有书库管理。
- 公共版权作品阅读。
- 开放授权作品阅读。
- OPDS 目录订阅。
- 官方免费阅读入口记录。
- 官方购买、借阅、出版社页面跳转。
- 书名、作者、卷数、封面、ISBN、出版社、语种等元数据索引。
- 对公共版权、开放授权或明确许可来源进行正文/EPUB 获取、缓存与站内阅读。
- 对本地/cached asset 提供内置阅读器和外部本地阅读器两类打开方式。
- 用户自定义来源，但必须有风险标记和能力限制。

### 不建议做

- 官方内置盗版源。
- 自动抓取受版权保护的正文。
- 绕过登录、付费、广告、DRM、地区限制。
- 伪装浏览器批量抓取商业站正文。
- 将社区插件市场变成资源站规则库。

## 最重要的产品取舍

**资源丰富度不靠正文聚合，而靠元数据和入口聚合。**

这意味着产品可以知道一本书在世界各处有哪些版本、哪些语言、哪些官方入口、哪些购买或借阅渠道，但不一定直接提供正文。

如果来源是公共版权、开放授权、用户自有文件，或经 ToS/授权确认允许第三方客户端下载/缓存的官方免费资源，
平台可以提供站内获取和内置阅读器阅读。否则默认只提供浏览器打开官方入口。

这种设计短期看不如盗版聚合刺激，长期看更稳定，也更适合开源公共品。

## 面向用户的表达

推荐表达：

> 一个开源、无广告、本地优先的轻小说平台；连接全球轻小说书目与合法阅读入口，用户掌握自己的书库，并可选择用浏览器、内置阅读器或本机其它阅读器阅读。

避免表达：

> 内置全网轻小说资源。

后者容易把产品推向版权高风险区。
