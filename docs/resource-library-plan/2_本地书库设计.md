# 本地书库设计

## 为什么不直接使用 Calibre 书库

Calibre 是成熟工具，但不适合作为本项目底层：

- 文件夹结构强绑定作者和书名，不适合轻小说复杂版本关系。
- 系列、卷、Web 版、文库版、译本、地区版本、修订版表达不够自然。
- 书库模型偏通用电子书，不适合“资源索引 + 本地阅读 + 在线入口”一体化。
- 很多用户并不使用 Calibre，强依赖会抬高门槛。

建议：**不以 Calibre 为核心，但支持 Calibre 导入。**

## 设计原则

1. **本地优先**
   - 没有网络也能阅读、搜索、标注、导出。

2. **内容与元数据分离**
   - 文件本体用哈希对象仓库存储。
   - 元数据、来源、进度、标注存在 SQLite。

3. **作品、版本、文件、来源分离**
   - 一本轻小说不是一个单独文件，而是一组跨版本、跨语种、跨来源的实体关系。

4. **可迁移**
   - 书库目录可以整体复制。
   - 标注和元数据可以导出为 Markdown / JSON。

## 推荐目录结构

```text
library/
├── library.sqlite
├── objects/
│   └── sha256/
│       ├── ab/
│       │   └── abcd...epub
│       └── ef/
│           └── ef01...txt
├── covers/
├── cache/
│   ├── metadata/
│   └── sources/
├── exports/
└── backups/
```

## 核心实体

### series

系列。

示例：

```text
无职转生
Re:从零开始的异世界生活
Sword Art Online
```

### work

作品本体。很多时候一个 series 只有一个 work，但保留 work 层可以兼容外传、短篇集、重制版。

### volume

卷或册。

字段建议：

```text
id
series_id
work_id
volume_number
title
subtitle
original_language
release_date
description
```

### edition

具体版本。

例如：

- 日文文库版
- 日文 Web 版
- 繁体中文版
- 简体中文版
- 英文版
- 修订版

字段建议：

```text
id
volume_id
language
publisher
translator
isbn
edition_name
publication_date
rights_status
```

### asset

实际可阅读对象。

可能是：

- 本地 EPUB
- 本地 TXT
- 本地 HTML
- 缓存的开放授权文件
- 只读的外部链接

字段建议：

```text
id
edition_id
kind              epub / txt / html / pdf / web_link
sha256
file_path
mime_type
size_bytes
created_at
updated_at
```

### source

来源。

字段建议：

```text
id
name
kind              opds / official_site / bookstore / library / user_import / metadata
base_url
license_policy
risk_level
enabled
```

### source_record

某个来源上的具体记录。

字段建议：

```text
id
source_id
entity_type       series / work / volume / edition / asset
entity_id
remote_url
remote_id
last_checked_at
availability
```

### reading_state

阅读状态。

字段建议：

```text
id
asset_id
locator
progress_percent
last_read_at
device_id
```

### annotation

标注、划线、批注。

字段建议：

```text
id
asset_id
locator
selected_text
text_hash
note
color
created_at
updated_at
```

定位建议：

- 主定位：EPUB CFI 或章节路径 + offset。
- 备用定位：选中文本前后文 hash。

## SQLite 的理由

- 单文件，易备份。
- Rust 生态成熟。
- 适合本地优先应用。
- 支持 FTS5，可做全文搜索。
- 不需要服务器。

## 桌面备份格式 v1

桌面端“备份数据”把用户选择的既有目录作为父目录，创建独立的
`lightnovel-reader-backup-v1-<timestamp>` 文件夹：

```text
lightnovel-reader-backup-v1-<timestamp>/
├── manifest.json
├── reader.db
├── library/
│   ├── library.sqlite
│   ├── objects/
│   └── covers/
└── plugins/
```

- `reader.db` 与 `library.sqlite` 从持锁连接执行 `VACUUM INTO`，不复制正在使用的数据库及 WAL/SHM。
- `manifest.json` 固定 `schemaVersion=1`，记录应用版本、创建时间和每个载荷文件的大小/SHA-256。
- `cache/` 可重建，`sync.json` 含同步令牌，二者明确排除；插件安装数据和插件私有 KV 随插件目录备份。
- 先写同级 `.partial` 临时目录并逐文件复核，全部成功后才原子改为正式目录；目标不能位于 app data 内。
- v1 的用户界面目前提供安全导出与只读校验预览，不提供覆盖现有数据的恢复按钮。校验会拒绝路径穿越、符号链接、重复/额外/
  缺失载荷和缓存/凭据/WAL 载荷，核对每个文件的大小与 SHA-256，再以只读连接执行两份 SQLite 的
  `PRAGMA quick_check`；通过后仅展示来源版本、书籍、进度、标注、插件与 EPUB 数量。
- 只读恢复计划会进一步比较当前数据与备份的书籍/进度/标注/插件/EPUB 数量，估算恢复前外部回滚点大小，
  明确采用“整体替换、不自动合并”，并要求关闭活动数据库连接后重启；较新应用版本生成的备份直接阻断。
- “创建外部回滚点（不恢复）”会复用同一导出链生成当前数据快照，完整复核后在回滚父目录原子写
  `lightnovel-reader-restore-preparation-v1-<timestamp>.json`；凭据固定 `restoreExecuted=false` 并钉住来源/回滚
  两份 manifest 的 SHA-256，不进入 app data，也不会安排下次启动覆盖。
- 只读恢复预检会限制凭据为外部普通 JSON 文件，重新完整检查来源与回滚点、凭据路径/状态/摘要，并读取 app data
  所在卷对普通用户可用的空间；staging 空间按来源载荷加 `max(10%, 64 MiB)` 安全余量阻断。预检固定
  `restoreAuthorized=false/restoreExecuted=false`，且要求真正执行前刷新回滚点，不能把历史准备凭据当成覆盖授权。
- native core 已有未接平台壳的启动期事务内核：在 app data 同级固定目录完整 staging，以阶段标记和同卷 rename
  移出/激活 `reader.db/library/plugins`，随后精确复核来源清单、SHA-256 与两份 SQLite；失败或中断优先从同卷
  `displaced/` 幂等恢复当前数据，即使外部来源与回滚目录暂时离线也能先自救。WAL/SHM 随当前数据移出，
  `sync.json`、缓存和未知顶层状态保持原位。
- 该低层内核不等于可用恢复功能。未来入口仍需在执行瞬间重跑空间检查、持锁刷新外部回滚点、明确二次确认，
  再原子写一次性启动请求并退出活动连接；真实退出/重启 smoke 和版本迁移策略完成前不得把“校验通过”等同于
  授权覆盖现有 app data。

## 去重策略

用 `sha256` 做文件去重。

同一个文件可被多个书目实体引用。例如：

- 用户导入同一本书两次，不重复存储。
- 不同来源指向同一文件，只保留一个 asset。
- 元数据修正不影响文件本体。

## 与 Calibre 的关系

建议作为导入源：

```text
Calibre metadata.db -> 解析 -> 写入本项目 library.sqlite
Calibre 文件路径 -> 计算 sha256 -> 导入 objects/
```

不建议直接把 Calibre 目录当主书库。
