# 桥接协议 v1.0-rc.1

> engine ↔ core 的全部通信面。代码层的权威定义在 `reader/src/platform/protocol.ts`
> (TS 侧)与 `reader/crates/reading-core` 的 serde 结构(Rust 侧);本文是语义说明与
> 演进规则。两边不一致时,以代码 + 本文档共同修订为准,不允许单边改。
> 文件名沿用 `v0.1` 是为了保持历史链接稳定;当前协议版本以 `src/platform/protocol.ts`
> 的 `PROTOCOL_VERSION` 为准。

## 设计原则

1. **壳是哑管道。** 平台壳(Tauri/Android/iOS/鸿蒙)只负责把消息从 WebView 搬运到
   reading-core 的入口,不解析、不加工、不持有业务状态。
2. **协议面 = `ReaderBridge` 接口。** 每个方法对应一条消息;新增能力 = 新增方法,
   不复用旧方法塞参数。
3. **DTO 与 serde 结构一一对应,wire 字段名一律 camelCase。**(Rust 侧用
   `#[serde(rename_all = "camelCase")]`;禁止再出现单字段 rename 造成的两侧漂移——
   v0.1 整理时已修复一例:标注的 `kind` 曾被 Rust 重命名为 `type`,导致保存标注
   反序列化失败。)
4. **错误返回统一为结构化错误码。** Tauri command 与原生 shell promise reject 时返回结构化
   `BridgeError`(`{ code, message, details? }`),引擎可据 `code` 分流(网络错误可重试、
   `httpStatus` 可显示状态)。浏览器/noBridge 开发兜底也尽量抛同形态对象;旧的 `e?.message || e`
   展示路径仍兼容。详见下文「结构化错误码」一节。
5. **消息面只传引用,大字节走资源通道。** 消息参数/返回值只含 id、路径、元数据;
   文件本体、图片等大字节一律走资源通道(URL scheme 或流式接口),不在消息里整块
   搬运。`library.importBytes` 是移动端沙盒的兜底,桌面端批量导入优先走路径版
   `library.import`。(2026-06-13 确立,见 DECISIONS.md)

### 章节预取语义（冻结前审计结论）

冻结前不新增 `chapter.prefetch` / `chapter.getBatch` 消息。原因：

- 现有 `chapter.get(href)` 已是幂等、可重复调用的章节 HTML 获取消息，core 侧有内存章节缓存与持久化
  parse cache；二次读取同章不重解析。
- `reader-engine` 已在 `ReaderCore.preloadAroundChapter` 做有界后台预取：当前章加载后异步请求前一章、
  后一章、后两章，且有前端 `chapterInflight` 去重与 `maxCachedChapters=10` 的内存上限。
- 桌面端当前瓶颈主要是首次解析/清洗与排版，新增批量 IPC 消息不会明显改善已验证的 P0/P1 链路，
  反而扩大冻结前协议面。

规则：`chapter.get` 可以被引擎用于前台加载和后台预取；预取失败不得打断当前阅读。若未来真机数据证明
跨章翻页延迟仍不可接受，再以新增消息方式引入 `chapter.prefetch(hrefs: string[]): Promise<void>`，
但冻结后的新增消息只能作为可选能力，不能改变 `chapter.get` 语义。

OPDS 补充约定：`opds.ingestEntries` 会把开放授权条目的 `acquisitionUrl` 持久化到 `source_record.acquisition_url`；`opds.downloadEpub(editionId, acquisitionUrl?)` 的第二参数可选，未传时壳侧必须从库内回读 `acquisitionUrl`，并继续强制 `rightsStatus=open_license`。

另有一条**资源通道**不走消息而走 URL scheme:章节正文里的插图以
`reader-img://localhost/<书内路径>` 引用,由壳注册的协议处理器从 core 按需读取。
新壳必须实现同名 scheme(或等价的拦截机制),这是协议的一部分。

### 资源通道审计（冻结前审计结论）

当前消息清单中只有两个大字节例外：

- `book.open(data: Uint8Array)`：文件选择器/移动端沙盒打开 EPUB 的兜底入口。
- `library.importBytes(data: Uint8Array, fileName?)`：移动端沙盒或无法获得路径时的导入兜底。

桌面批量导入、书库开书、OPDS/青空获取都不在消息面搬运 EPUB 大字节：桌面优先传路径或 id，HTTP
下载在平台壳侧完成，core 写入对象仓库后再返回 `LibraryBook` 元数据。章节正文返回清洗后的 HTML 字符串；
插图、封面和本地文件不内联进消息：

- 书内插图走 `reader-img` URL scheme 按需读取当前已打开 EPUB 的图片资源。
- 本地封面/缩略图路径先由 `resource.url` 转为 WebView 可加载 URL。
- 远程封面保持来源 http(s) URL，不经消息面代理。

冻结后新增能力不得新增“整本书/图片/二进制 blob 直接塞进 JSON 消息”的协议；必须使用路径、id、
URL scheme、HTTP 流或未来明确设计的流式资源通道。

v0.7 插件安装同样遵守该规则：桌面壳通过 `plugin.selectPackagePath` 取得 zip 路径，
`plugin.inspectPackage` / `plugin.installPackage` 在壳侧读取文件并交给 core 校验/写入；
协议消息不传插件 zip 字节，也不执行插件代码。

官方插件仓库安装同样不在消息面搬运 zip 字节：`plugin.repository.load` 只传索引 URL 并返回索引 DTO；
`plugin.repository.inspectPackage` / `plugin.repository.installPackage` 只传 HTTPS 包 URL、期望 SHA-256 与可选签名 DTO。
桌面壳负责 HTTP 下载和大小上限检查，core 负责索引/包校验、SHA-256 核对、安装预览与写入。
安装命令必须重新下载并再次校验哈希，不能信任此前预览阶段的临时结果。

## DTO 字段约定

- `AppUpdateInstallProgress`：`appUpdate.install` 的可选本地进度回调 DTO，`stage` 为
  `downloading|installing`，`downloadedBytes` 是累计已下载字节，`totalBytes?` 仅在服务端提供长度时存在。
  该回调只传数值状态；安装器字节始终留在平台 updater 内，不进入桥接消息面。
- `BookInfo.metadata`:由 EPUB OPF 提取,当前包含 `title`,以及可选的 `author`、`language`、`description`、`series`、`seriesIndex`。其中 `series/seriesIndex` 兼容 Calibre 常见 `calibre:series` 写法与 EPUB 3 `property` 写法。
- `LibraryBook`:本地书库入库后的稳定记录,字段包含 `id/title/author/language/series/seriesIndex/description/filePath/fileSize/coverPath/thumbPath/addedAt/lastReadAt`。`coverPath` 是对象仓库内提取出的封面文件路径,前端展示前必须经 `resource.url` 转换。
  - **v0.5-b 起新增可选实体字段**(查询时 JOIN asset/edition/volume 回填,符合"只增可选字段"规则):`seriesId`、`volumeId`、`editionId`、`availability`(`local|remote|missing|cached`)。本地书恒有值;远程 `metadata_only` 条目无 asset 时为空。`availability` 决定该条目能否站内阅读,否则只展示元数据 + 外链。
  - **v0.5-c 起 `filePath`/`fileSize` 转可选**:读路径已锚定 `edition`(一个版本 = 一个书架条目),不再读 `books`。远程 `metadata_only` 条目无本地文件,这两字段缺省;`library.open` 对无 `filePath` 的条目返回错误,前端应据 `availability` 改走外链。条目 `id`:本地 = 内容哈希(= `asset.id`,供 open/标注/进度同键),无 asset 时回退 `edition.id`。
  - **v0.5-d 起新增可选 `remoteUrl`**(读路径从 `source_record` 子查询回填):来源外链。本地条目为空;远程/受版权条目点击后由 `shell.openExternal` 跳此地址。封面 `coverPath` 对远程条目是来源给的 http(s) URL(直接加载,不经 `resource.url`),本地条目才是需转换的文件路径——前端按 `availability` 区分。
  - **v0.5-e 起新增可选 `rightsStatus`**(读路径从 `edition.rights_status` 回填):授权状态,与资产可得性正交。`public_domain` 可由 `library.acquireRemote` 获取正文并转为 `availability=cached`;`official_purchase`/`unknown` 等非公共版权条目不得下载正文,只能通过 `remoteUrl` 跳官方页。
  - **v0.6 起新增可选 `acquisitionUrl`**(读路径从 `source_record.acquisition_url` 回填):合法开放正文的获取链接,必须与 `remoteUrl` 分离;`remoteUrl` 始终表示官方/来源页面外链,`acquisitionUrl` 只供 `open_license` 等可缓存资源执行获取后阅读。
- `PluginManifest`:源插件安装包内 `manifest.json` 的强类型映射，包含 `apiVersion/id/name/version/entry/domains/permissions/capabilities/legal`。`permissions` 当前为 `http|kv`，`capabilities` 当前为 `browse|resolveUrl|fetchMetadata|acquire`，`legal.kind` 当前为 `public-domain|open-license|official-free|user-declared`；`legal.termsUrl?` 是源站 HTTPS 条款地址。
- `PluginValidation`:core 侧 manifest 策略校验结果，包含 `officialRepositoryEligible`、`requiresUserLegalConfirmation`、`requiresSourceTermsConfirmation` 与 `warnings`。`user-declared` 或需要源站条款确认的 `official-free + HTTP` 插件必须在 `plugin.installPackage` 中传入 `confirmUserLegal=true` 才能写入本地插件目录。
- `PluginInstallPreview`:插件安装前预览 DTO，包含 `manifest`、`validation` 与 `entrySize`。只用于展示权限/域名/合规风险，不代表插件已经安装或可执行。
- `InstalledPlugin`:已安装源插件元数据，包含 `PluginInstallPreview` 全部字段、`installedAt` 与 `enabled`。`enabled=false` 表示 QuickJS 运行时不得加载该插件；`enabled=true` 仍只是必要条件，每次 host 调用还需继续经过 manifest 权限、域名和尺寸策略门。重新安装同 id 插件会先清理旧插件目录，避免旧入口文件残留。
- `PluginPackageSignature`:官方插件仓库索引里的可选包签名，字段为 `algorithm/keyId/value`；当前算法固定 `ed25519`，
  `value` 是 zip 原始字节签名的标准 Base64。`keyId` 必须属于壳编译内 keyring，预览/安装下载后均重新验签。
- `PluginRepositoryEntry`:官方仓库单条候选插件，包含完整 `manifest`、`packageUrl`、`packageSha256`，以及可选 `packageSize/sourceUrl/signature`。`packageUrl/sourceUrl` 必须 HTTPS，`packageSha256` 必须是 64 位 hex。
- `PluginRepositoryIndex`:官方仓库索引 DTO，包含 `schemaVersion`、可选 `generatedAt` 与 `entries`；core 负责校验条目上限、重复插件 id 与官方资格。
- `PluginRepositoryValidation`:官方仓库索引校验摘要，包含 `entries` 与 `warnings`；当前正式发布公钥尚未配置，
  unsigned 条目会显示人工白名单警告，声明签名但 keyId 未知的索引直接拒绝。
- `PluginRepositoryCatalog`:桥接返回的官方仓库索引结果，包含 `index` 与 `validation`。
- `PluginSearchResult` / `PluginSearchPage`:插件 `search` 的标准化结果；单条结果包含 `url/title`与可选 `author/coverUrl/summary`，页结果包含 `results/hasMore`。
- `PluginChapterRef` / `PluginBookDetail`:插件 `getBook` 的标准化结果；书籍包含 `url/title/chapters` 与可选元数据，章节引用包含 `url/title/group?`。
- `PluginChapterContent`:插件 `getChapter` 返回的 `title/html`；`html` 离开 runtime 前必须经 reading-core 安全清洗。
- `PluginTestFlowResult`:`plugin.testFlow` 返回值，包含一页 `search`、第一本 `book` 和第一章 `chapter`。
- `PluginSourceDescriptor`：`source.list` 返回的正式来源描述，包含 `id/name/description?/language?/legal/capabilities`；
  只列已启用插件，不暴露安装时间或安装校验状态。

## 结构化错误码

为支持引擎按错误类别分流（网络错误可重试、HTTP 状态可显示、参数错误不可重试），
桥接 promise reject 时返回结构化 `BridgeError` 而非裸字符串。同步方法 `resource.url` 不属于 promise
reject 语义;其平台实现应尽量保持纯转换、不做 I/O。

- **权威定义**：Rust 侧 `src-tauri/src/lib.rs` 的 `BridgeError`（`#[serde(rename_all = "camelCase")]`），
  TS 侧 `src/platform/protocol.ts` 的 `BridgeError` / `BridgeErrorCode` / `isBridgeError`。Rust command
  使用的新 code 必须同步 Rust 构造器;TS 壳侧专用 code 必须同步 TS 类型与本文档。
- **wire 形状**：`{ code: string, message: string, details?: string }`。`code` 是稳定分类串，
  `message` 永远可读（中文/英文），`details` 是可选附加信息（如 HTTP 状态码）。
- **兼容性**：`BridgeError` 总带 `message`。引擎要按类别处理时用 `isBridgeError(e)` 判定后读
  `e.code`;极旧或第三方壳若仍返回字符串，旧的 `e?.message || e` 展示路径仍可读，但官方 Tauri 壳
  不再依赖裸字符串 reject。
- **当前消费点**：`src/main.ts::formatError` 已使用 `isBridgeError` 识别结构化错误，并在 OPDS
  源列表、添加/移除源、浏览/搜索 feed、加入书架、下载 EPUB、批量加入书架等 UI 错误展示中显示
  `message`、稳定 `code` 与可选 `details`。

错误码清单（新增 code 必须同步 Rust 构造器、TS `BridgeErrorCode` 与本表）：

| code | 含义 | 典型场景 |
|---|---|---|
| `invalidArgument` | 参数非法/缺失 | 空 URL、空搜索词 |
| `storageError` | 本地存储/SQLite/锁错误 | 数据库读写、Mutex poisoned、落库失败 |
| `parseError` | 解析失败 | OPDS feed XML/JSON 解析失败 |
| `networkError` | 网络传输失败 | reqwest 请求/读响应失败 |
| `httpStatus` | HTTP 非 2xx 响应 | OPDS/在线元数据源/开放授权下载返回错误状态（`details` 带状态码） |
| `notFound` | 目标不存在 | 找不到 OPDS 源 / 远程条目 |
| `forbidden` | 因授权/版权拒绝 | 非 `open_license` 条目请求下载正文 |
| `platformError` | 平台壳能力失败 | 系统浏览器/外部阅读器打开失败、无原生 bridge 的开发兜底 |

## 各壳的映射方式

| 壳 | 映射 |
|---|---|
| Tauri 桌面(现役) | 方法 → 同名 Tauri command(`src/platform/tauri.ts` 是唯一映射点) |
| Android(规划) | 方法 → `WebView.addJavascriptInterface` 单入口 + JSON 编解码 → UniFFI 调 core |
| iOS(规划) | 方法 → `WKScriptMessageHandler` 单入口 + JSON → UniFFI 调 core |
| 鸿蒙(远期) | 方法 → ArkWeb JS bridge + NAPI 调 core |
| Web(远期) | 方法 → reading-core 编译为 wasm32,直接调 WASM 导出函数,无 IPC |

移动壳采用「单入口 + 消息名分发」而非逐方法注册,以保证加消息不改壳。

## 纪律与强制

- 引擎代码**只允许 import `src/platform/`**;`@tauri-apps/*` 出现在其他位置即违规。
  由 `reader/scripts/check-arch.mjs` 强制,已接入 `npm run build`。
- 业务逻辑一律写入 `crates/reading-core`,Tauri command 只做参数搬运。
- 协议冻结关键事实由 `reader/scripts/check-protocol-freeze.mjs` 强制核对，已接入 `check:project` 与
  `npm run build`。该脚本检查 `PROTOCOL_VERSION`、TS `BridgeErrorCode`、Rust `BridgeError`
  构造器错误码与本文档错误码/冻结规则是否一致。
