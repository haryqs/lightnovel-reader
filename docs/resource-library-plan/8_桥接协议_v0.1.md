# 桥接协议 v0.1

> engine ↔ core 的全部通信面。代码层的权威定义在 `reader/src/platform/protocol.ts`
> (TS 侧)与 `reader/crates/reading-core` 的 serde 结构(Rust 侧);本文是语义说明与
> 演进规则。两边不一致时,以代码 + 本文档共同修订为准,不允许单边改。

## 设计原则

1. **壳是哑管道。** 平台壳(Tauri/Android/iOS/鸿蒙)只负责把消息从 WebView 搬运到
   reading-core 的入口,不解析、不加工、不持有业务状态。
2. **协议面 = `ReaderBridge` 接口。** 每个方法对应一条消息;新增能力 = 新增方法,
   不复用旧方法塞参数。
3. **DTO 与 serde 结构一一对应,wire 字段名一律 camelCase。**(Rust 侧用
   `#[serde(rename_all = "camelCase")]`;禁止再出现单字段 rename 造成的两侧漂移——
   v0.1 整理时已修复一例:标注的 `kind` 曾被 Rust 重命名为 `type`,导致保存标注
   反序列化失败。)
4. **错误以字符串消息返回**(目前),引擎侧负责包装展示;v0.5 冻结前评估是否需要
   结构化错误码。
5. **消息面只传引用,大字节走资源通道。** 消息参数/返回值只含 id、路径、元数据;
   文件本体、图片等大字节一律走资源通道(URL scheme 或流式接口),不在消息里整块
   搬运。`library.importBytes` 是移动端沙盒的兜底,桌面端批量导入优先走路径版
   `library.import`。(2026-06-13 确立,见 DECISIONS.md)

## 消息清单(v0.1)

| 消息 | 方法签名 | 语义 |
|---|---|---|
| `book.open` | `openBookFromBytes(data: Uint8Array): Promise<BookInfo>` | 从内存字节打开 EPUB(文件选择器路径),core 解析结构并缓存首章 |
| `book.openPath` | `openBookFromPath(path: string): Promise<OpenedBook>` | 按路径打开(书库进入);bookId 由 core 按内容 SHA-256 前 32 hex 计算 |
| `book.close` | `closeBook(): Promise<void>` | 释放当前书内存 |
| `chapter.get` | `getChapter(href: string): Promise<string>` | 返回清洗后的章节 HTML(core 内有章缓存) |
| `library.listCalibre` | `listCalibreBooks(library: string): Promise<CalibreBook[]>` | 只读 Calibre metadata.db,列出全部 EPUB |
| `library.import` | `importLibraryBook(path: string): Promise<ImportOutcome>` | 按文件路径导入 EPUB 到自有书库对象仓库(objects/<id>.epub),按内容哈希去重 |
| `library.importBytes` | `importLibraryBookFromBytes(data: Uint8Array, fileName?: string): Promise<ImportOutcome>` | 从文件选择器/移动端沙盒传入 EPUB 字节并导入对象仓库;无标题元数据时用 fileName 兜底 |
| `library.list` | `listLibraryBooks(): Promise<LibraryBook[]>` | 列出自有书库,最近阅读优先 |
| `library.search` | `searchLibraryBooks(query: string): Promise<LibraryBook[]>` | 搜索自有书库标题/作者/系列;CJK ≥3 字走 trigram FTS,短词 LIKE 兜底 |
| `library.open` | `openLibraryBook(id: string): Promise<OpenedBook>` | 按自有书库 id 打开对象仓库里的 EPUB |
| `library.touchLastRead` | `touchLibraryLastRead(id: string): Promise<void>` | 打开书库书籍后更新最近阅读时间 |
| `annotation.save` | `saveAnnotation(a: Annotation): Promise<void>` | upsert 标注 |
| `annotation.list` | `listAnnotations(bookId: string): Promise<Annotation[]>` | 按书列出标注 |
| `annotation.delete` | `deleteAnnotation(id: string): Promise<void>` | 删除标注 |
| `reading.saveProgress` | `saveProgress(p: ReadingProgress): Promise<void>` | upsert 阅读位置(引擎防抖 800ms 调用) |
| `reading.getProgress` | `getProgress(bookId: string): Promise<ReadingProgress \| null>` | 开书时取上次位置,无记录为 null |
| `resource.url` | `resolveFileUrl(path: string): string` | 本地文件路径 → 当前 WebView 可加载的 URL(同步,各壳实现不同) |

另有一条**资源通道**不走消息而走 URL scheme:章节正文里的插图以
`reader-img://localhost/<书内路径>` 引用,由壳注册的协议处理器从 core 按需读取。
新壳必须实现同名 scheme(或等价的拦截机制),这是协议的一部分。

## DTO 字段约定

- `BookInfo.metadata`:由 EPUB OPF 提取,当前包含 `title`,以及可选的 `author`、`language`、`description`、`series`、`seriesIndex`。其中 `series/seriesIndex` 兼容 Calibre 常见 `calibre:series` 写法与 EPUB 3 `property` 写法。
- `LibraryBook`:本地书库入库后的稳定记录,字段包含 `id/title/author/language/series/seriesIndex/description/filePath/fileSize/coverPath/thumbPath/addedAt/lastReadAt`。`coverPath` 是对象仓库内提取出的封面文件路径,前端展示前必须经 `resource.url` 转换。
  - **v0.5-b 起新增可选实体字段**(查询时 JOIN asset/edition/volume 回填,符合"只增可选字段"规则):`seriesId`、`volumeId`、`editionId`、`availability`(`local|remote|missing|cached`)。本地书恒有值;远程 `metadata_only` 条目无 asset 时为空。`availability` 决定该条目能否站内阅读,否则只展示元数据 + 外链。

## 各壳的映射方式

| 壳 | 映射 |
|---|---|
| Tauri 桌面(现役) | 方法 → 同名 Tauri command(`src/platform/tauri.ts` 是唯一映射点) |
| Android(规划) | 方法 → `WebView.addJavascriptInterface` 单入口 + JSON 编解码 → UniFFI 调 core |
| iOS(规划) | 方法 → `WKScriptMessageHandler` 单入口 + JSON → UniFFI 调 core |
| 鸿蒙(远期) | 方法 → ArkWeb JS bridge + NAPI 调 core |
| Web(远期) | 方法 → reading-core 编译为 wasm32,直接调 WASM 导出函数,无 IPC |

移动壳采用「单入口 + 消息名分发」而非逐方法注册,以保证加消息不改壳。

## 纪律与强制

- 引擎代码**只允许 import `src/platform/`**;`@tauri-apps/*` 出现在其他位置即违规。
  由 `reader/scripts/check-arch.mjs` 强制,已接入 `npm run build`。
- 业务逻辑一律写入 `crates/reading-core`,Tauri command 只做参数搬运。
